## Topology and roles

The upstream VMware NAT network connects to R1's WAN interface. TRUNK-SW1 on R1 connects to TRUNK-R1 on SW1. SW1 distributes VLANs through access ports; R1 hosts all six VLAN gateways and performs routing.

## IPv4 firewall principles

- `input` handles packets destined for R1 itself; `forward` handles packets passing through R1 to another host; `output` handles packets generated by R1.
- Rules are processed from top to bottom within the relevant chain. The first matching `accept` or `drop` rule determines whether the packet is allowed or blocked; subsequent rules in that chain are not evaluated for that packet.
- Both input and forward first accept `established,related,untracked` traffic, then drop `invalid` traffic.
- `INPUT default deny` and `FORWARD default deny` drop remaining traffic. The reviewed export contains no restrictive output rules.
- WAN NAT `masquerade` changes the source address but does not replace firewall access rules.

## Rule behavior and monitoring scope

- The dedicated DNS UDP allow rule duplicates port 53 in the AD UDP rule.
- CCTV DNS/NTP ports are allowed to any non-private WAN destination, not just the two DNS servers supplied by DHCP. Protocol payloads are not inspected.
- The general WAN accept rule does not force domain clients to use internal DNS exclusively or filter applications/websites.
- MANAGEMENT has broad trust based on source IP.
- Traffic within a VLAN may not pass through R1; these rules do not replace endpoint firewalls.
- The reviewed SW1 export contains no `/ip firewall filter` rules. IP Services restrictions are not a complete host firewall.
- NTP clients are configured on R1/SW1.
- ICMP checks of VLAN gateways do not establish access-port health, endpoint availability, or network throughput.
