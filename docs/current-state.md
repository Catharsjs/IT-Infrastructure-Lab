# Поточний стан стенда

Дата звірки: **31.08.2026**.

Документ відділяє фактичну конфігурацію від перевірки її поведінки. Джерела — експорти RouterOS, скриншоти, виводи команд і результати ручної практики. Первинні матеріали ще не включені в цей етап публікації.

## Фізична платформа

| Параметр | Значення |
|---|---|
| Призначення | Окремий домашній ПК для лабораторії |
| Гіпервізор | VMware Workstation; точна версія ще не зафіксована |
| CPU | AMD Ryzen 5 2600 |
| RAM | 16 GB DDR4 |
| GPU | NVIDIA GTX 1060 6 GB; не визначає продуктивність серверних ролей |
| Обмеження | Не всі VM працюють одночасно через RAM |

Фактичний розподіл vCPU/RAM/дисків, тип сховища та номери всіх VMnet потребують інвентаризації. Планові значення не видаються за виміряні.

## Профілі запуску

- **AD/GPO:** R1, SW1, DC01, USER-WS-001.
- **SMB:** попередній набір плюс FS01; Ubuntu можна вимкнути.
- **Monitoring:** R1, SW1, Ubuntu та потрібні цільові сервери; FS01/клієнт — за потреби.

Це спосіб організувати ручну практику, не підтверджений бюджет RAM або гарантія продуктивності. VM завершуються штатно; вимкнений сервер не вважається доказом блокування Firewall.

## Active Directory та Group Policy

- Навчальний DNS-домен: `local.domain`; NetBIOS: `NETLAB`.
- Відомий контролер домену: DC01. Точні domain/forest functional levels не зафіксовані.
- OU NETLAB містить Admin-Accounts, Disabled Objects, Groups, Servers, Service Accounts, Users і Workstations.
- Тестовий користувач розташований у `NETLAB/Users/IT/Developers`, комп'ютер — у `NETLAB/Workstations/Developers`.
- У членстві користувача видно GG-групи відділу/ролі й DL-групи файлових дозволів. Повна матриця вкладеності та Share/NTFS ACL буде оформлена окремо.
- Default Domain Policy застосовується до комп'ютера, її User Configuration порожня. Тому N/A у user-scope gpresult не був помилкою доставки.
- Окрема `GPO-WS-Developers-AutoLock` прив'язана до OU комп'ютерів Developers. Machine inactivity limit — 900 секунд. Отримання підтверджене gpresult, фактичне блокування — ручним тестом.
- Копії GPO створено на DC01 і перенесено на фізичний серверний ПК. Налаштування AutoLock імпортовано в неприв'язану `TEST-AutoLock-Recovery`, значення 900 перевірено.

Імпорт налаштувань у нову GPO не є тестом відновлення всього AD або оригінальної політики з її ідентичністю та прив'язками. Копія на тому самому фізичному диску не захищає від відмови цього диска.

## Мережа й файловий сервер

VLAN, DHCP, порти та доступ описані в [мережевому плані](architecture/network-plan.md).

Два широкі дозволи CLIENTS ↔ DC01 вимкнено під час практики. Після змін успішно виконані DNS SRV-запит, gpupdate і nltest /dsgetdc з /force. Це не тест усіх доменних функцій або кожного дозволеного порту.

SMB-доступ і групова модель були перевірені раніше за підтвердженням учасника лабораторії. Новий повний протокол позитивного/негативного доступу та повторний тест після змін Firewall не виконані. Відновлення файлу з backup не підтверджене.

## Моніторинг і журнали

- Zabbix Agent 2 на DC01: Running, TCP10050 Listen; шаблон Windows by Zabbix agent. Точна версія Agent 2 окремим виводом не підтверджена.
- Hardware dashboard показує CPU, RAM і зайнятість файлових систем Windows/Linux, а також графіки.
- Network Health містить шість ICMP-хостів для шлюзів VLAN, таблицю status/loss/latency і графіки.
- ICMP до адрес одного R1 не показує справність усіх кінцевих вузлів і access-портів.
- Frontend у показаній конфігурації працює через HTTP/8080. TLS фронтенду/агентів, SNMPv3 та зовнішні сповіщення не підтверджені.
- У Security Event Log DC01 розібрані 4672 і 5379. Це практика читання журналів, не повний аудит змін AD або централізований збір логів.

## Рівень перевірки

| Категорія | Що відомо |
|---|---|
| Підтверджено виводами/скриншотами | DHCP VLAN50/60, source VLAN30, DNS SRV, gpupdate, DC discovery, недоступність TCP8291 із VLAN30, CCTV DNS/NTP і невдалий HTTPS, dashboards |
| Підтверджено ручною практикою без повного артефакту | Автоблокування через 15 хвилин, GPO backup/import, копії поза VM, попередній SMB-доступ |
| Видно в конфігурації | VLAN table, DHCP-пули, IPv4 Firewall, NAT, обмеження SSH/WinBox, NTP clients |
| Не підтверджено | Повна VLAN-матриця, позитивний контроль WinBox із MGMT у фінальному протоколі, повне відновлення, SNMPv3, доставка alert/recovery, централізований аудит |

## Відомі відкриті питання

1. Перед етапом конфігурацій потрібен актуальний експорт R1 після остаточного збереження змін. Старий перевірений файл містить ще активні широкі дозволи.
2. Потрібні очищені докази, точні ресурси VM й відповідність VMnet; поточна документація не забезпечує автоматичне розгортання з нуля.
3. Початковий DNS timeout/Server Unknown, повна синхронізація часу, IPv6 і MAC-management не розслідувані до завершення.
4. Backup/restore AD, FS01, Zabbix і MikroTik не перевірено; RPO/RTO не заявляються.
5. WireGuard і Dual WAN відкладені. Docker, AWS, IaC та Kubernetes не входять у поточну реалізацію.
